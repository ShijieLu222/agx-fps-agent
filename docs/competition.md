# FPS 规则与提交流程

核对日期：2026-11-15。来源：[官方开发指南](https://agx.cool/#/docs/fps)、[赛事规则](https://agx.cool/#/competitions/2a97f94f-816a-52b7-b4b8-5925db160245/rules)。历史对局保留自己的冻结合同，须记录实际 `rules_version` 与版本身份。

## 游戏目标

- 一个 agent 控制一名独立玩家，固定 10 个席位组成 5v5；课程小组与游戏队伍不是同一概念。
- MR12：先赢 13 回合；第 12 回合后交换攻守，清空装备并将现金重置为 800；12:12 平局，默认无加时。
- 攻方安包并保卫，或在安包前消灭守方；守方阻止安包或拆包。安包后攻方全灭不会取消炸弹。
- 地图为 Dust2、Mirage、Borgo、Molo、Nevaio，一场使用一张。地图选择不保证每五场各出现一次。
- 排名依据团队胜负/平局，击杀、现金、回合差不直接额外加分；平台前 10 局属于暂定成绩。

## 关键时钟

| 项目 | 当前值 |
| --- | --- |
| 物理 / 决策 / 录像 | 60 / 20 / 24 Hz |
| 买枪冻结 / 未安包 live / 回合结算 | 6 / 115 / 5 秒 |
| 买枪窗口 | 冻结 + live 前 25 秒，仍须在己方购买区 |
| 安包 / 拆包 | 3 秒 / 有工具包 5 秒、无工具包 10 秒 |
| 炸弹引信 | 40 秒 |
| 拆包距离 | 严格小于 2.8 米 |

安拆包需符合位置、阵营、着地和低速条件并连续保持动作。开火、装填、切枪和投掷可能阻断交互。同 tick 到期与拆除完成时爆炸优先。

## 合法观察与动作

自身状态在 `me`；`visible` 只含当时可见敌人的合法信息；`sounds` 是粗粒度方向/距离；可用允许的队友、炸弹、消息与回执字段。敌方精确隐藏位置、血量、库存、真实比赛种子均不能作为策略输入。

首次观察包含 `map`，后续通常省略；按 `map_id` 与 `static_schema_hash` 缓存。公开几何、导航候选和录像画面不等同权威碰撞或当时合法观察。

动作返回字典。移动和转向为有限数 `[-1, 1]`；`fire/reload/jump/...` 为 bool；动作槽 `weapon_slot=0/1/2` 对应主武器/副武器/刀；`use` 为 `none/plant/defuse/pickup`。缺省字段为中性默认；额外键、错误类型、NaN、越界值可能造成故障。

## 资源与打包

- 每席整局累计 64 CPU 秒，包括初始化，不随回合或半场重置。
- 初始化上限 2 秒；首次 `act` 上限 1 秒；之后每次 50 ms。解码、策略执行和编码也占预算。
- 必须尽早检查异常与超限；策略被禁用后后续为中性控制。
- ZIP 根必须有 `agent.py`。本基线只提交这个文件，FPS 不需赛车的设计书。
- 允许辅助 Python 模块和受限数值 NPZ；不能提交 venv、requirements、wheel、原生库或 pickle。
- ZIP/解包上限 64/128 MiB、最多 64 项；单源码 256 KiB、总源码/design 1 MiB。精确运行时限制以提交指南为准。

## 第一次参赛

1. 用课程登记的评分账号登录，进入正确的 FPS 比赛。
2. 创建/选择本人 Agent，上传 `dist/agx-fps-agent.zip`。
3. 等待准入结果；保存版本 ID、bundle hash、合同身份和任何故障代码。
4. 确认「当前代码版本」更新。2026-11-15 网页说明通过校验后自动使用最新通过版本参赛；如手动切换，选择已接受版本。新版本只用于之后指派的新对局。
5. 等待正式对局完成，确认 ranked result、faults 和榜单信息。
6. 从本人对局页下载日志并查看回放。日志在线下载窗口为 30 天，及时本地归档。

## 排期与成绩

这是常驻赛，可随时报名。课程作业说明每两小时比赛；2026-11-15 登录后的报名页显示本轮 `2026-11-15T04:00:00+00:00`，即北京时间 **11 月 15 日 12:00**。网页显示的短时间没有注明时区，应按完整时间字段转换，后续排期以当时页面为准。

可用参赛版本会自动匹配其他账号；排期不是保证个人一定被排入对局。排名在每场结算后更新，前 10 场为暂定成绩。网站未给出固定出分分钟数；等待排队、运行和验证完成后，在「我的对局」查看结果与回放。55 分钟执行上限不是常规耗时承诺。

## 本地验证的边界

本项目的单元测试使用合成观察。`replay_check.py` 可以检查新代码在过去观察上的异常、输出类型和本地耗时，但新动作会改变未来世界，因此不能用它声称新版本获胜。它检查日志末尾完整性标记，不代替服务端导出的全部完整性核验。

官方工具包只提供地图数据、标定与近似优化示例。若以后自建模拟器，应按本人合法日志标定，并用未参与调参的真实比赛验证误差。
