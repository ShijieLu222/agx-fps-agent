## 代码问题与比赛证据

### 1. 行进时摄像机几乎只服务于寻路

v7 `move()` 同时根据下一路点计算移动与 `yaw_rate`，并把 `pitch` 拉向水平。路点在东边就一直看东边，即使公开的守方来向在北侧。`quiet_action()` 只在过去已经看见敌人时预瞄，没有未接敌时的主动观察。

最新 Molo 第 3、4、5、8、9、11 回合，本人整回合无敌人视野、未开枪便死亡。用公开枪击起点与本人受击前的实际朝向作赛后对齐，若干首次受击的水平偏角分别为：

| 回合 | 相对当时视角的来弹方位 | 距离约 | 当时本人可见敌人数 |
| --- | --- | --- | --- |
| 3 | +74.8° | 97.6m | 0 |
| 4 | -61.2° | 68.2m | 0 |
| 5 | +77.7° | 52.3m | 0 |
| 8 | +110.3° | 77.7m | 0 |
| 9 | -60.7° | 94.3m | 0 |
| 11 | -58.5° | 95.0m | 0 |

这是**观察扇区不足的证据和推断**，不是证明所有无视野都仅由视角造成；遮挡、高低差仍可能存在。上述敌方坐标仅用于离线解释，不写入策略。

### 2. 无视野受击后会撤，但不转头搜索

v7 `unseen_damage_escape()` 规定 `yaw_rate=0, pitch_rate=0`。回撤确实发生，却保留了刚刚未能发现攻击者的朝向。

最新 Molo 第 3 回合，tick 8115 首次观察到掉血，策略立即沿已走地面轨迹后退；之后生命约 83→67→52→34→19→2，连续约 0.45 秒内朝向一直保持 -1.571，仍未发现敌人。说明旧的“收到伤害就原路退”并非没有执行，而是执行后缺少获取反击信息的步骤。

第 9、11 回合也有受击后继续处在危险路段的情况。原路后退不保证立即进入掩体；不能仅延长后退时间就宣称解决。

### 3. 部分交火窗口短于停稳等待

最新 Molo 进攻半场 199 次有射程内合法目标的观察中，56 次速度尚不满足 `<0.25m/s`。第 14 回合仅 5 次可打目标观察，全部尚未停稳，本人没有开枪便死亡。

这提示后续可研究提前预瞄、预减速与按枪械精度选择开火速度。**本轮不直接放宽速度阈值**：官方目录中步枪移动散布显著更大，盲目移动连射可能降低有效伤害；应取得自己的运动/精度响应后再独立验证。

### 4. 下包并没有全面失效，瓶颈主要发生在到点之前

两场 Molo 本人 plant/defuse 请求均为 0；在 Borgo 第 2 回合有 60 次连续 plant 请求并实际完成 1 次安包。这说明不能再把“没有下包”一概归因于早期的反向制动 bug。应区分携包途中死亡、未到有效区域、到点后交互失败。

### 5. 仍有下一轮值得优化的模块

- 经济：只买 AK/M4、护甲和拆弹钳，未购买头盔，也缺少中间预算选择。最新进攻半场收到 8 次头部命中；但购买优先级涉及下一回合经济，应单独比较，不能把头盔当作普遍解决方案。
- 目标与队友协作：攻击包点按回合奇偶轮换，队友是独立策略，“自己的统一包点规则”不能保证全队统一；目前基本未用队友区域/信号调整护包与支援。
- 守点与回防：已完成到点停车，但没有完整的持角、轮转与残局风险判断。
- 导航：仍排除梯子，图无路径时存在直接朝目标移动的退化；路网候选不能等同真实可通行边。这些需要独立的地图与闭环用例，避免和本轮视角改动混在一起。

## 本轮 v8 已实现

1. **进攻行进时将观察方向与寻路分离。** 每 2 秒的观察周期中，1.2 秒查看地图公开的守方出生区域方向，0.8 秒回到寻路原有朝向。公开区域是搜索方向，不声称敌人仍在那里，也不触发开火。
2. **无视野受伤后搜索两侧。** 首先查看一侧约 0.6 秒，再查看另一侧，整体 1.8 秒内结束。先检查哪一侧只由公开区域方向或席位决定，不读取隐藏攻击来源。连续受击不反复重置第一侧。
3. **沿本人已走过的地面轨迹后退。** 保留对跳落、楼层、高差与断裂轨迹的保护，不因转头而虚构可回退路径。若没有安全回撤轨迹，仍可在现有导航动作上搜索视野。
4. **可见交战、下包、拆包优先。** 获得当前合法敌人观察就交还原射击控制；不对地图区域、声音猜测或回放坐标开火。盲目/腾空/跳跃/交互时不施加观察区域控制；普通防守导航沿用 v7。

v8 ZIP SHA256：`d948b68705b72dc4c3931d1e4fd36b3bffeb683ebd6b9f85abf75dfbe5fc5fa0`。包只含 `agent.py`。

## 验证与局限

- **113 项测试通过**。新增当前视角下世界移动方向验证、三物理子步旋转的简化到点闭环、侧面目标的简化视野获取、受击搜索不重复重置、交战/目标优先、盲目/腾空保护及换图/换回合清理。
- v7 原基线 103/104 旧测试通过。失败用例把“旧目标记忆到期”错误地绑定为 `yaw_rate=0`；v6 的落地路点判定可能合法回看起始节点。本轮改为检查记忆清除及合适路点转向。另一旧安全用例的零转头断言按本轮有意行为改为允许搜索，仍验证原路回撤、不开盲枪。
- 三场历史检查 **89,575 次，无异常、无非法动作**。v7 与记录完全一致；v8 改变 12,713 次动作，改变字段仅 `yaw_rate/pitch_rate`。在这些固定观察上，开火、移动、购买、安拆包控制保持原值。
- 本机含 JSON 的总策略 CPU 分别约 0.63、0.62、1.06 秒，最慢回调约 0.28ms；不是平台 CPU 保证。
- 历史输入不会随新动作变化，不能宣称新策略已多看到敌人、多击杀或赢下旧比赛。视角变化也会影响未来真实观察及物理子步中的行进误差；简化测试无法覆盖官方碰撞与完整视野算法。
- 三场均参与诊断，不是留出集。新的观察周期是待验证策略参数，公开出生区不是敌人实时分布模型；需要其他地图和新的 Molo 对局验证。

建议下一阶段先保持 v7 基线可回滚，单独验证视角改动。记录每次死亡前是否见过敌人、首次掉血至首次发现目标时间、首枪延迟、进攻每回合伤害、携包到点与实际安包、路径停滞、faults。至少按地图与攻守拆分，再考虑经济和射击参数；不会承诺固定场数后一定涨分。
