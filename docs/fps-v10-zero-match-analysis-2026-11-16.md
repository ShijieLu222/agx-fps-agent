## 代码定位与两种必须区分的数据格式

已发布 v10 的 `Player.act()` 在第一次决策缓存地图，第二次决策调用 `load_map()`，再调用 `build_guard_plans()`。初始化在 buy 阶段也执行，虽然当前是进攻方，仍会构建守点计划。因此 tick 3 与地图初始化阶段吻合；尚未执行 live 阶段支援、回防或对枪分支。

本地使用发布源码 SHA256 `e83b4c1fb3bbd4ccd91ddf14747760332d6b33ad8006008dfc7e87249f7cd1b1`，直接加载公开 Mirage 地图副本：

```python
hints = row.get("bot_waypoints", {})
published = hints.get("hold" + name, [])
```

该副本 `bot_waypoints: null`，所以 `hints` 为 None，后一句触发 `AttributeError: 'NoneType' object has no attribute 'get'`。字典 `.get(key, default)` 只有在键缺失时才返回默认值，键存在但为 null 不会使用默认值。

受控本地比较：保留 null → 失败；移除此键 → 成功构建两个包点计划；改为 `{}` → 成功。代码风险确定存在，该行从 v9 已存在，v10 没有新增它。

**但这不等于本场已经确认由该异常造成。** 在之前的 Nevaio 比赛中，公开回放地图同样可显示 null，而本人真实 training 输入根本没有该键；同一段代码因此正常运行。公开回放可能补充空字段。Mirage 的实际 observation 是否同样省略该键，必须读取这场本人的 training.jsonl 才能确认。

另一个待排查项是第二次回调的 CPU 限制：地图建图与守点计划集中在这次回调，而从第二次开始上限为 50ms。处理过空值的 Mirage 本地初始化约 10–14ms，不能推出服务器一定不超时，也不能推出本场就是超时。当前没有本场服务器 CPU 回执或 fault code。

## 之前验证的缺口

155 项测试和六场 169,907 次历史输入检查当时确实通过；但六场只覆盖四张不同地图：Nevaio、Dust2、Molo、Borgo，没有 Mirage。本地历史输入检查也不等于服务器实际预算验证，平台准入通过不等于所有地图的整场运行通过。

需要补齐：五张地图的真实首次观察及第二次回调；可选字段缺失、null、空容器的独立用例；地图初始化预算留余量；本人故障日志可用时准确复现原 fault。若故障为 CPU 超时，应考虑将初始化放在首调 1 秒宽限内或分批处理；若是字段异常，应修正格式处理，不能只吞掉异常并留下半初始化状态。
