# FPS v8 首场实战、策略清单及高伤害选手比较

分析时间：2026-11-16，北京时间。最新场为 [12:00 Dust2](https://agx.cool/#/matches/e2e40a26-1715-4a31-946a-3787284c5a52)，12:11 完赛，使用 v8。本人队伍 1:13，个人 2 杀 / 13 死 / 556.135 伤害，评分 1195.561 → 1151.265（−44.296）。

**主要问题是“能走到包点，却不会选择守点位置和观察入口”，加上射击冷却的决策/物理时序错位、偏保守的开火及瞄准策略。最新场不是主要因为子弹打不中：29 次枪击事件中 28 次产生命中。** 这不能证明所有地图枪法都好；前一场 Nevaio 的命中表现明显较低。

上一轮判断应修正：Molo 防守侧曾有好成绩，不足以把防守逻辑视为已解决。v8 的主动观察只改进攻；本场先守 12 回合，防守 1:11 时已陷入绝境。两场不同地图、队友与对手，不能用 v7 13:2、v8 1:13 推断 v8 的净因果效果。

## 数据可信度与范围

- 最新 v8 本人席位为 **6（零起始；UI 选手 #7）**，不是之前三场的席位 1。队伍号在换边后保持不变。
- 原始训练导出核验 metadata、席位、版本 ZIP 指纹、行数、字节数、SHA256 和末尾完成标记。v8 ZIP 指纹 `d948b68705b72dc4c3931d1e4fd36b3bffeb683ebd6b9f85abf75dfbe5fc5fa0`。
- 最新 v8 **18,887 次决策全部精确复现，fault 0**；前一场 v7 **20,435 次全部复现，fault 0**。分析中的方法包装未改变动作。不是上传错版本、异常退出，或将别人的席位误认为本人。
- 对最近五场公开事件全部核验 descriptor、字节数、行数和 SHA256；击杀只计 `kill_reward.killer`，不能把助攻也算成击杀。
- 抽查 Dust2 82 帧、Nevaio 30 帧、Molo 15 帧；索引与对应 41 个公开帧分块均验证 SHA256。抽样用于具体片段，不代表整场移动频率。
- 别人的源代码和私有观察不可见；下文只区分代码可确认的本人策略、公开事件可确认的行为，以及合理推断。
- 本文“伤害”按平台 `hit.hp_damage` 累加，与页面计分口径一致；该字段在最后一枪可能超过目标剩余 HP，不能解释为净减少的生命值。“头部命中占比”是头部 hit 事件数 / 全部 hit 事件数，不是爆头击杀率。

## 当前 agent 实际策略

| 模块 | v8 实际执行 | 当前局限 |
|---|---|---|
| 决策 | 每 3 个物理 tick 回调一次，即 20Hz；单一确定性规则策略，有跨回合的路径风险记忆 | 没有训练得到的策略网络，也不在线更新模型参数 |
| 经济 | 无主武器且够钱先买攻方 AK / 守方 M4A1；护甲低于 50 再买甲；守方再买拆弹钳 | 不买头盔、手雷、烟、闪；没有中档枪选择、团队经济或专门的存钱规则 |
| 进攻目标 | 按回合奇偶在 A/B 间轮换；看见掉落炸弹会去拾取；安包后到已知炸弹附近 | 不跟随当前携包队友决定主攻方向，没有约定共同进点 |
| 防守目标 | 根据 `seat % 5` 分配包点；本场席位 6 固定 B | 没有根据敌情、队友覆盖或入口压力调整守位；包点中心被当成守点位置 |
| 寻路 | A*，排除梯子；给高台、失败边及近期受伤路线增加代价；卡住尝试退路或换方向 | 优化的是到达目标，并未优化掩体、暴露角度、交叉火力；部分地图边未碰撞验证 |
| 到达目标 | 普通目标距离 <0.65m 停止，保持 1.2m 到达滞回；请求 `yaw_rate=0.15` 扫视 | 没有持角、掩体探头、搜索扇区或预瞄入口的状态机 |
| 行进观察 | 攻方每 2s：前 1.2s 看公开 CT 出生区域方向，后 0.8s 看导航方向 | 不是预测敌人位置，也不是每个路口清角；普通防守及原地守点不使用此改动 |
| 目标选择 | 选择当前可见、射程内目标，偏近者；已有目标只有在另一人近至少 25% 时切换 | 不按敌人露出部位、武器威胁、是否正在攻击自己等综合排序 |
| 瞄准 | **胸 → 腹 → 头**；仅露头须连续稳定可见 6 tick；补偿公开后坐 | 只要胸部可见便不主动瞄头；没有距离/目标状态自适应收益选择 |
| 开火 | 地面、速度 <0.25m/s、水平/垂直误差各 <0.025rad（约 1.43°），检查武器与冷却 | 停稳和转向可能错过短暂窗口；冷却检查存在下面的时序问题 |
| 射击节奏 | 手枪按触发/释放节奏；步枪 42 tick 周期中前 24 tick允许射击，后18 tick暂停 | 没有随距离、后坐、敌人动作调整连射与点射；近战也有固定停火期 |
| 失去视野 | 短暂停稳；短时记住最后看见的位置用于转头，超过约3s清除 | 不盲射；有限等待，但也会丢失重新抢线机会 |
| 无视野受伤 | 在最近走过的连续地面轨迹上回退；转头搜索一侧0.6s，再另一侧，最长1.8s | 长时间原地站立没有可回退轨迹，往往只转头；不能靠受伤后搜索弥补预先失守 |
| 目标交互 | 安拆包优先，先停稳；携包/拆包有远距离交火时间预算；炸弹位置未知则查公共包点 | 缺少根据队友与敌情选择站位/时机；本场没有安拆包请求 |
| 信息利用 | 使用本人状态、可见敌人、公开地图、炸弹与有限历史 | **当前没有读取 `sounds`、队友消息和队友站位来做战术决策** |

## 问题一：到包点中心站住，不等于守住入口

Dust2 B中心 `[167.3735, 60.2617, 20.2032]`。第2–12回合本人通常停在约 `[167, 60.5, 20.12]`，目标达成后请求原地扫视。**这是到点策略本身，不是反复撞墙或寻路卡住。**

剔除下文有异常片段的第10回合，其余11个防守回合共有417.4s存活观察，其中193.7s处于代码的“已到点”分支，占46.4%。这个占比只是观察时间统计，不代表全部时间都具备开枪机会。

首次受击相对视角方位：第2回合 −126.8°、第3回合 −160.3°、第7回合 −135.7°、第9回合 +102.1°。这些回合均未看见敌人便死亡。攻击者距本人约16.6–18.9m，说明近距离侧后方暴露仍很严重；不能把所有不可见都归因于朝向，遮挡也会影响。

防守11次死亡，从第一发受击到死亡的中位数只有 **0.30s**。满转向输入在这些片段约3rad/s，转90°约0.52s；受伤后再花0.6s检查第一侧，常来不及。

- 第4回合：首次看到敌人只剩30.1HP，约0.117s后死亡，未开枪。
- 第5回合：首次看到敌人只剩45.7HP，未开枪。
- 第8回合：首次看到敌人只剩18.7HP，未开枪。
- 已在原地站很久时，最近连续地面轨迹没有长度，回退分支不成立，搜索只改变朝向、移动仍为0。不能称为回撤成功。

**修改方向：把“去包点”与“守包点”拆开；选择可退回的掩体边、优先观察公开入口方向，站位和朝向共同规划。仅加快原地转圈不能解决暴露。**

## 问题二：连射被冷却检查额外拖慢

第6回合与 northwind 的对枪，双方在约18.75m处打躯干；本人先开枪。公开事件与本人日志精确对齐：

| match tick | 本人 M4A1 | northwind AK |
|---:|---|---|
| 19540 | 第一枪命中，24.30伤害 | 受击后剩约54.5HP |
| 19546 | 等待 | 第一枪命中，27.08伤害 |
| 19549 | 第二枪命中，24.31伤害 | |
| 19552 | | 第二枪命中，27.09伤害 |
| 19558 | 第三枪命中，24.31伤害 | 第三枪命中，27.09伤害 |
| 19564 | 仍未打出第四枪，死亡 | 第四枪击杀，自己剩约5.9HP |

本人19539的决策在19540产生第一发。随后19545这次观察的武器/本人 `shot_ready` 都是19546，速度为0，瞄准误差也满足阈值。但 `clock_ready(..., tick)` 以19545判断，拒绝开火；19548才再请求，于19549开枪。19554、19563重复同样问题。

因此短连射间隔是 **9 tick=0.15s**，而对手是 **6 tick=0.10s**。在这个片段中，实际射速为6.67发/s vs10发/s；这是开火节奏差，不是单发命中差。AK与M4的伤害差也存在，不能将整段败因全部归为射速，更不能宣称改完一定反杀。

该时序损失叠加步枪固定的24/42 tick开火窗口。近期多场本人步枪常见9 tick间隔及24 tick间断；并非v8才引入。应将“动作在未来物理子步执行”纳入冷却判断，并独立检查持续扣扳机、弹药、后坐和换枪的真实语义；不应把所有时钟一律加1。

## 问题三：有声音线索，但策略完全不利用

第4回合 tick12945、12972、12999，本人合法输入均有 `footstep / right / mid`，最后一次在首次中枪前4 tick。策略仍请求 `yaw_rate=+0.15` 通用扫视；首次受击的攻击来向在右后方约−86.9°。

第8、9回合首次受击前，也有右侧中距离脚步提示。声音不提供身份、精确方位或敌我区分，不能据此开枪，也不能断言声音一定来自随后开枪的人；但它可以调整搜索方向、减速或提高入口注意力。当前代码连这个有限信息也没用。

### 本场第一名：优势主要是交火机会与生存，不是全靠爆头

- 77次枪击 vs 本人29次，是2.66倍；平均平台伤害/枪击事件约29.91 vs19.18，是1.56倍；两者合起来约4.14倍总伤害。
- 他12/14回合有开火、4次死亡全部曾开枪；本人6/14回合有开火、7次死亡一枪未开。
- 他71/77枪击事件产生至少一次子弹命中，约92.2%；本人28/29约96.6%。一枪穿透可能多个 hit，故不能直接把72/77当命中率。
- 抽查第1、6、12回合的首枪位置均接近A区通路 `[150–152, 135]`，第2回合位于该侧更外侧 `[125,132]`；他并不是每局都来B点打本人，不能把他的全部伤害解释为“专门针对我”。
- 抽查首枪附近速度0–0.63m/s，多为站姿；他存在比本人 `<0.25m/s` 更宽松的实际开枪运动状态。但采样帧最多早2 tick，只能支持这些片段的行为，不能还原其精确速度阈值。
- 该选手步枪也多为9 tick间隔，说明更快射速不是所有高伤害者的共同秘密。购买记录包括5次头盔，既可能是政策，也受经济/存活影响；没有手雷投掷。
- 同队同侧的 murmur 防守也有846.2伤害、40枪，本人为454.2、19枪；差距并不完全由攻守阵营不同解释。

### 123 与 solstice：同场能比较输出机会和射击节奏

10:00 Nevaio中，123伤害2535.4，solstice2529.5，两人只差5.84。本人1084.3，而且三人同队同侧。

- 123在15/15回合都开过枪，130次枪击；本人12/15回合，98次。前3回合首枪抽样落在同一条约`[42–43,84]`通路，均蹲姿、速度0。能确认的是稳定进入交火位置并输出，不能断言其内部有手工配置的卡点。
- solstice射出183发，虽只有76次产生子弹命中，仍累积2529.5伤害。他132次AK枪击中的近间隔，有110次是6 tick；本人该场AK近间隔以9 tick、24 tick为主。
- 123不以极高爆头占比取胜，solstice也不是最高命中率。说明“更早有效接敌、持续输出”可以比单纯追求命中率更重要。

### o55man：当前最值得学习的稳定高输出参照

- 两场Molo连续伤害第一，跨攻守都有输出；08:00守方24/1、2778.6伤害，进攻14/7、1983.3伤害。
- 06:00他与本人同队、同进攻半场：他进攻15/8、2375.0伤害，本人0/8、427.3伤害。更适合发现个人策略差距，仍非相同路线/装备的受控试验。
- 06:00全场129枪 vs64枪，平均伤害/枪约26.67 vs12.75：既有更多出手机会，也有更高每枪收益。
- 两场头部命中占比约25–27%，本人同期约2.6–2.9%。这支持研究条件化瞄头，不证明其代码永远瞄头。
- 他不少步枪间隔12–18 tick，慢于本场northwind的6 tick，但输出更高。不能仅复制最快连射；其命中部位与交火机会也值得学习。

### Verstappen：高头部命中、高单发收益，也有明显攻守差异

- Borgo 65次命中中35次头部，100次枪击产生3785.0平台伤害，伤害/枪37.85。
- 其中守方2893.7伤害、21/6，攻方891.3、6/9；下一场Molo攻方又是4/9。不是所有地图/阶段都强。

## 一处需要独立保留的数据异常

第10回合是本人队伍唯一胜回合，原因是未安放超时。公开帧tick31000、33000、35000中，十人的位置、朝向和速度均完全重复；部分人速度非零而位置不变。本人合法观察同一时段也保持位置/朝向不变，尽管持续请求转头。

所以这段至少存在模拟推进或记录状态冻结的异常迹象，不能把该回合算成“成功守点战术”的证明，也不能把它解释成本人独有的卡住问题。仅有回放无法确认平台内部根因；没有向平台提交反馈或替用户发送消息。前述停点占比已排除整个第10回合，避免异常长时间夸大结论。

## 下一步优先级

1. **先修射击时钟与节奏**：用第6回合边界、换枪/装填、手枪松扳机、步枪连射构建明确时间语义验证。应减少无意等待，而非无条件开火。
2. **补完整防守状态**：到点后选择可撤的掩体边和入口朝向，有限使用声音优先级；分离“导航目标”“持角目标”和“撤退目标”。不要用包点中心加慢转圈替代防守。
3. **加入条件化瞄准与接敌减速**：稳定近中距离、已停稳且头部可见时评估瞄头；远距/不稳定目标保留躯干；结合地图路口预瞄与减速，避免看见人才开始全速刹停。
4. 再研究中档经济/头盔、携包队友协作、道具；当前数据不支持先大改所有模块。

本轮只分析、生成可复核数据和报告，**未改动线上agent或上传v9**。v8当前仅一场，尚不足以评价其跨地图收益；新策略须以新对局验证。
