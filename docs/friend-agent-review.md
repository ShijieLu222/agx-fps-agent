## 本轮选择合入的思想

- **交火制动：** 按自身水平速度与朝向做反向制动，落地、低速且瞄准就绪时才开火。
- **射击节奏：** 手枪在请求之间释放扳机；步枪的开火与恢复窗口由实际请求启动，避免依赖全局 tick 的任意相位。
- **短时战斗状态：** 暂时保持接触后的蹲姿；短时记住合法看见的位置用于预瞄，失去可见性不向记忆目标开火。
- **武器连续性：** 交战时空主武器可切到已装弹副武器；保持进行中的装填，避免每拍重新请求。
- **目标协作：** 攻方使用一致包点选择，守方分散到包点；在合法观察获知已安装炸弹位置后可保留该位置，回合与地图变化清除。
- **目标交互：** 先减速再持续安包/拆包，保持有效活动武器槽；保留本项目原有的任一包点处理与近处拆包逻辑。

另外加入当前仍可见敌人的目标保持机制，减少两敌距离微小交替导致的转枪。以上只是可解释行为改进，未证明线上胜率提升。

## 不直接覆盖及暂不合入

1. **保留 v1 自身时钟判断。** 原包在 `gun.shot_ready=False`、`me.shot_ready=False`、瞄准完成时仍返回 `fire=True`，因布尔值参与数值比较被视为已过期；本项目保留布尔就绪与数值截止时钟的区分。
2. **保留地图身份失效保护。** 原包只在新 `map` 数据处理时检查 ID，`static_schema_hash` 变化而未给新静态数据时仍使用旧节点。本项目保留地图 ID/schema 失效清理。
3. **保留 2 米拆包策略阈值。** 原包阈值为 0.95 米，已知炸弹距 1.5 米时继续移动；官方合法范围严格小于 2.8 米。过度逼近会增加卡住和错过拆包窗口的风险。
4. **不启用未标定投掷物。** 原包固定抛角与自身闪光转身时钟，没有验证过的落点。已复现：HE 计划启动后敌人在 2 米处重新可见，原包仍继续投掷准备而不进入交战。本轮不引入该优先级风险。
5. **不复制压缩地板救援图。** 其分层、有界搜索可作为后续实验，但不能由公开候选证明穿墙/可达性；当前保留已有几何 A*，先用本人对局日志确定是否需要额外救援层。
6. **保留现有经济策略。** 原包的 eco/full/force 判断及队友资金投票会显著改变整场资源分配，应与交火与移动修复分开验证，不能仅凭更复杂就认为更强。

## 本地检查的边界

原包在本机的初始化约 23.1 ms；五图出生点到 A 点的分层救援搜索分别需要 6–29 个回调批次，单批次最大约 0.704 ms。它没有显示明显的局部 CPU 超限，但不包含平台 JSON/调度开销，也不证明整场 64 CPU 秒预算或路线有效。

v2 最终代码通过 45 项回归测试（原有 26 项与新增 19 项）。新增测试包括交火时保护已经开始的主枪装填，而尚未开始装填的空主枪可以切到副枪。对 30000 次随机合成观察的独立扫测未发现协议错误，验证了 742 次实际开火请求和 3108 次进行中装填的保持条件。小型三节点地图上的策略计算合计约 0.177 CPU 秒、最慢回调约 0.023 ms；另用 4096/10000 节点人工网格测得 A* 单次最慢约 3.814/9.287 ms。这些数据仅检查分支行为与本机局部耗时，不模拟真实对局，不包含 JSON/平台开销。

v2 的回归测试覆盖实际选择合入的行为，最终结果、包指纹和平台生效记录由[迭代日志](../experiments/iteration-log.md)记录。真实对局完成后仍需检查 faults、装填/切枪、安拆包完成率、可见敌人交火和导航停滞。
